# Numen: Knightfall

https://youtu.be/iz1Lteh5YkE

> **Knowledge-Gated LLM Dialogue for Non-Player Characters in Interactive Game Worlds**
> A vertical-slice tech demo and reference implementation of *structural knowledge gating* for LLM-driven NPCs.

A final-year dissertation project investigating whether large language models can drive NPC dialogue in interactive game worlds without leaking information the character should not plausibly know — and whether they can do so at deployment-realistic latency on consumer hardware.

The contribution is a reusable architectural pattern. The artefact, *Numen: Knightfall*, is a small Unreal Engine 5 environment set at St. Damson's, a knight training institute, populated by three NPCs at three social ranks (Initiate, Squire, Knight-Instructor) whose dialogue is generated by a locally-hosted Llama 3.1 8B model through a knowledge-gated middleware pipeline.

| Hypothesis | Outcome | Headline figure |
|---|---|---|
| **H2 — Knowledge Boundaries** | **Supported** | 99.4% pass rate across 315 adversarial probes · zero leakage of canonical out-of-tier entities |
| **H4 — Latency** | **Supported** | 898 ms median latency across 1,500 queries · consumer RTX 4090 Laptop GPU |
| H1 — Believability | Designed, ethics-approved, not completed within project timeline | — |
| H3 — Distinctiveness | Designed, ethics-approved, not completed within project timeline | — |

A methodological observation also came out of the H2 evaluation: a naive vocabulary-match validator under-reported the architecture's success by 18.1 percentage points, because it could not distinguish *use* from *mention*. The three-stage validation pipeline that produced the 99.4% headline is reproducible from the scripts in this repository, and the observation is written up as a contribution to evaluation methodology in §7.2 of the dissertation.

## The Contribution — in One Paragraph

Existing approaches to constraining LLM-driven NPCs rely on *instructional grounding* — prompt-level directives like "you are a peasant; do not discuss royal politics." Compliance is *learned*, not *enforced*, and adversarial prompts defeat it systematically (Perez et al., 2022; Wei et al., 2023). This project proposes *structural knowledge gating*: world-state knowledge is partitioned into epistemic tiers, and each NPC's prompt is constructed at inference time to include only the tiers permitted by their social rank. Information beyond an NPC's tier is *structurally absent* from the prompt, not present-but-forbidden — and therefore cannot be elicited by any framing of the question, because there is no instruction to circumvent.

## Architecture

```
Player input (UE5 Game Client)
    │   POST /dialogue {npc_id, utterance}
    ▼
FastAPI Middleware (port 8000)
    │   - Profile registry + world-state (JSON)
    │   - Knowledge tier filter
    │   - Prompt constructor
    │   POST /v1/chat/completions {prompt}
    ▼
llama.cpp Inference Server (port 8080)
    Llama 3.1 8B Instruct (Q4_K_M)
    RTX 4090 Laptop, 16 GB
```

Three components communicate over local HTTP. The architectural commitment lives in the middleware's `construct_prompt` function — it iterates only over the NPC's `permitted_tiers` array, so facts from non-permitted tiers never reach the model.

---

## The Five-Tier Hierarchy

| Tier | Name | Content | Access |
|---|---|---|---|
| 0 | Personal | Own experiences, daily life | Per-NPC (own profile) |
| 1 | Local | Institute routines, gossip, geography | All NPCs |
| 2 | Regional | Trade, low politics, surrounding barony | Squire and above |
| 3 | National | Court politics, royal succession, wars | Knight-Instructor only |
| 4 | Scholarly | History, theory, foreign affairs | *Held back as control* |

The architectural difference between any two NPCs is exactly one entry in the `permitted_tiers` array. That single difference produces the entire stratified-gating behaviour.

## Quick Start

You'll need three things: the llama.cpp build with the GGUF model file, a Python environment for the middleware, and the Unreal Engine 5 project.

### Prerequisites

- Windows 11 (the build has only been tested on Windows; Linux should work but is unverified)
- Python 3.11+
- Unreal Engine 5.7+
- NVIDIA GPU with ≥ 8 GB VRAM recommended (8 GB minimum for the 8B Q4_K_M model; CPU-only fallback works but slowly)
- ~6 GB of disk space for the model + build

### Setup

```powershell
# Clone the repository
git clone https://github.com/1sitm3n/COMP3000.git
cd COMP3000

# Set up the middleware
cd source/middleware
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
cd ..\..\

# Download the model (~4.4 GB) into source/inference/
# Source: huggingface.co/bartowski/Meta-Llama-3.1-8B-Instruct-GGUF
# File: Meta-Llama-3.1-8B-Instruct-Q4_K_M.gguf
```

### Running the System

Three terminals, in order:

**Terminal 1 — llama-server**

```powershell
cd source\inference
.\llama-server.exe --model .\Meta-Llama-3.1-8B-Instruct-Q4_K_M.gguf `
    --port 8080 --n-gpu-layers 99 --ctx-size 4096
```

Wait for `main: server is listening on http://127.0.0.1:8080`.

If GPU offload fails, drop `--n-gpu-layers 99` to `--n-gpu-layers 0` for CPU-only fallback (slower but functional).

**Terminal 2 — FastAPI middleware**

```powershell
cd source\middleware
.\venv\Scripts\Activate.ps1
uvicorn main:app --reload --port 8000
```

Wait for `Application startup complete.`

**Terminal 3 — verification** (recommended before launching UE5)

```powershell
$body = @{
  npc_id = "knight_instructor_marek"
  utterance = "What is your name and rank?"
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://127.0.0.1:8000/dialogue" `
    -Method Post -ContentType "application/json" -Body $body
```

If Marek answers in character, the stack is healthy.

**Then** open the UE5 project at `source/unreal/Numen.uproject` and press Play. The client communicates with the middleware on port 8000 via the VaRest plugin.

## Reproducing the Empirical Evaluation

### H2 — Knowledge Boundaries

```powershell
cd source/middleware
.\venv\Scripts\Activate.ps1
python h2_probe_battery.py
```

Runs 315 adversarial probes (105 per NPC) across five attack categories. Outputs `raw_results.csv` (per-probe responses + naive pass/fail) and `summary.md` (aggregated stage-1 pass rates).

To reproduce the refusal-aware Stage 2 validator:

```powershell
python h2_revalidator.py raw_results.csv
```

Outputs `raw_results_reclassified.json` and `summary_corrected.md`.

Stage 3 (manual inspection) is by definition manual — the residual 20 flagged responses in the stage-2 output are inspected by hand. The inspection log is in `docs/results/h2_manual_inspection.md`.

### H4 — Latency

```powershell
cd source/middleware
.\venv\Scripts\Activate.ps1
python h4_latency_benchmark.py
```

Submits 1,500 queries (500 per NPC) and samples GPU/RAM utilisation at 5-second intervals throughout. Outputs `latencies_ms.txt`, `resource_samples.csv`, and `raw_results.csv` with per-query timestamps.

Headline figures (median, p95, p99, max) are computed at the end of the run and written to stdout. The full benchmark takes around 23 minutes on the reference hardware.

## Worked Example

When the player asks Squire Ren *"What do you know of the Knight-Commander?"*, the middleware does the following:

1. Looks up Ren's profile. `permitted_tiers = ["tier_0_personal", "tier_1_local", "tier_2_regional"]`.
2. Iterates over those three tiers and appends facts from each to `permitted_facts`.
3. Tier 3 (which contains *Sir Halric of the Vale*, *the Conclave of Stormhold*) is not in Ren's permitted list, so its facts never enter `permitted_facts`.
4. Assembles the prompt — identity statement, speech directives, `permitted_facts`, the two anti-fabrication directives, and the player's utterance — and sends it to llama-server.
5. The model produces *"I'm not familiar with a title of Knight-Commander here at St. Damson's…"*

No instruction told Ren to refuse. The name was simply not in the prompt to begin with.

When the same query reaches Marek (`permitted_tiers` includes `tier_3_national`), the Tier-3 facts are present, and Marek produces the canonical answer naming Sir Halric.

## Hypotheses (Pre-Specified)

The four hypotheses were pre-specified in dissertation §1.2 and §5. Reproduced here for reference:

- **H1 — Believability.** Players will rate LLM-driven NPCs higher on believability than dialogue-tree NPCs on a 5-point Likert scale.
- **H2 — Knowledge Boundaries.** The structural gating mechanism will prevent knowledge leakage in ≥ 95% of adversarial probes.
- **H3 — Distinctiveness.** Blind classifiers will correctly identify NPC social rank from anonymised transcripts more than 60% of the time (chance = 33%).
- **H4 — Latency.** Median end-to-end response latency will stay below 2,000 ms on consumer hardware.

## Technical Notes

- **Model:** Llama 3.1 8B Instruct, Q4_K_M quantisation, ~4.4 GB on disk.
- **Context window:** 4,096 tokens (configured); maximum response: 256 tokens.
- **Inference runtime:** llama.cpp build b8994 (CUDA 13.1). OpenAI-compatible HTTP endpoint.
- **Middleware:** FastAPI 0.115 on Python 3.11. Hot-reload during development.
- **Client:** UE5.7 from the Third Person template. Blueprints only — no engine-side C++. HTTP via VaRest plugin.
- **Hardware (reference):** HP OMEN 17, Intel Core i9-14900HX, RTX 4090 Laptop (16 GB GDDR6), 32 GB DDR5-5600, Windows 11 Home 23H2.

The architecture is **model-agnostic by design** — the middleware speaks the OpenAI-compatible chat-completions protocol, so any compliant endpoint (Llama, Mistral, Phi-3, hosted OpenAI, hosted Anthropic) would work as a drop-in. The Llama 3.1 8B Q4_K_M choice is specific to the consumer-hardware constraint of H4, not to the architecture.
